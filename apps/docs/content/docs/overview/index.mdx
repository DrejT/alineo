alineo runs AI coding agents inside sandboxed containers — and gives you a control plane for a
swarm of them.

An agent is a spec and a prompt:

```ts
import { Alineo, textOnly } from "alineo";
import { SQLiteAdapter } from "@alineo-labs/sqlite";

const agent = await Alineo.load(
  {
    name: "hello",
    cli: "pi",
    provider: "nvidia",
    model: "nvidia/nemotron-3.5-lightning-30b-a3b",
    env: { NVIDIA_API_KEY: "${NVIDIA_API_KEY}" },
  },
  { adapter: new SQLiteAdapter("./.alineo/ledger.db") },
);

for await (const chunk of textOnly(agent.prompt("Write and run a Python hello world."))) {
  process.stdout.write(chunk);
}
```

That's a real container. The agent installs packages, clones repositories and runs what it
writes — and it cannot reach your machine.

[Run it yourself →](/docs/agent/quickstart)

## It starts in seconds

The first `load()` installs the [Pi](https://pi.ai) CLI into a `node:22` sandbox and checkpoints
the container. Every load after that restores the snapshot instead: **~3 seconds rather than
~90**. The cache key is the spec's packages, setup steps and CLI version, so it invalidates
itself when it should.

Nothing to configure — [snapshotting](/docs/agent/concepts/snapshots) is on by default.

## Your process is not the agent

The agent lives in the container, not in your Node process. Kill the process, come back
tomorrow, pick the same agent back up:

```ts
const agent = await Alineo.reattach(sandboxId, { adapter });
```

Pi restarts with `--continue`, so the session it was in the middle of is still there. This is
also what makes a swarm survive a daemon restart — see
[crash recovery](/docs/alineod/concepts/crash-recovery).

## Fork a running agent

This is the part that isn't like anything else.

```ts
const reviewer = await agent.spawn("./agents/reviewer.json");
```

The child is forked from the parent's **live** sandbox. The checkout, the installed packages,
the files the parent wrote — all of it is already on the child's disk. No fresh clone, no
second `npm ci`.

So you clone a repository once and review it three ways at the same time:

![A lead agent clones expressjs/cors, forks three reviewer agents from its live sandbox, pauses one and steers another mid-review, then an editor waits for all three and merges their findings.](/docs-assets/swarm-demo.gif)

A child can also declare `waitFor` on its siblings. alineod holds it unspawned until they
settle, then writes each one's result into its sandbox before its first turn — which is how the
editor above merges three reviews it never had to poll for.

## Steer it mid-turn

```ts
await agent.steer("Focus only on the auth path — drop the unrelated findings.");
```

The message lands after the current tool call finishes and before the next model call. The
agent does not restart and does not lose its context.

`pause()` freezes the container outright; `resume()` continues from the same instruction. An
agent that is thinking about the wrong thing is a correctable mistake, not a wasted run.

## Gate what it can do

Every tool call the agent wants to make can be held for a decision — yours, or a policy's:

```ts
agent.prompt(task, {
  onPermission: (req) =>
    req.tool === "bash" && req.target.startsWith("rm ")
      ? { kind: "reject", feedback: "Deleting files is out of scope." }
      : { kind: "once" },
});
```

`reject` hands the feedback back to the model as the reason. Leave `onPermission` off and the
requests surface on the stream instead, for a human to resolve with
`agent.resolvePermission()`.

Egress is enforced out-of-process at the sidecar, so a compromised agent cannot decide to skip
it. Credentials can be bound so that the key never becomes a container environment variable at
all — it is injected into matching outbound requests instead, where the agent can use it but
never read it.

[The permission gate →](/docs/agent/concepts/permissions)

## Everything is on the record

Every exec, tool call and state transition is appended to a SQLite or Postgres ledger before
anything derived from it is updated. That single path is what makes the rest work: crash
recovery replays it, `resume()` restores from the last checkpoint and serves completed execs
from cache, and an auditor gets the whole run rather than a summary of it.

## Drive a swarm from any language

Everything above is also a wire protocol. `alineod` is a daemon that speaks HTTP and
Server-Sent Events, so a swarm doesn't need an SDK in your language — it needs `curl`.

```bash
curl -s localhost:4600/runs -H 'content-type: application/json' -d '{
  "spec": { "name": "lead", "cli": "pi", "provider": "nvidia",
            "model": "nvidia/nemotron-3.5-lightning-30b-a3b",
            "env": { "NVIDIA_API_KEY": "${NVIDIA_API_KEY}" },
            "spawnDepth": 1, "maxAgents": 5 },
  "prompt": "Clone expressjs/cors and report the commit under review."
}'
```

`${NVIDIA_API_KEY}` is resolved from **alineod's own** environment, so the key never travels in
the request. One `GET /runs/:id/events` connection then carries every agent's progress, tagged
with the agent that produced it.
