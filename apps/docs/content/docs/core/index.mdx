`@alineo-labs/sandbox` gives you a running container as an ordinary object. You call `client.sandbox()` to get one,
call methods on it, and close it when you're done.

```ts
import { Sandbox } from "@alineo-labs/sandbox";
import { SQLiteAdapter } from "@alineo-labs/sqlite";

const client = new Sandbox({
  baseUrl: "http://localhost:8080",
  adapter: new SQLiteAdapter("./ledger.db"),
});

const sb = await client.sandbox({
  image: "ubuntu:22.04",
  resources: { cpu: "500m", memory: "512Mi" },
});
try {
  await sb.exec('echo "hello world"').pipe(process.stdout);
} finally {
  await sb.close();
}
```

Two sandboxes are two variables. There is no session object, no pool to configure and no special API for
concurrency — [`maxConcurrency`](/docs/core/concepts/sandboxes) caps it if you want a cap.
[Quickstart →](/docs/core/quickstart)

## Every exec has three shapes

`sb.exec()` returns an [`ExecHandle`](/docs/core/api-reference/exec-handle), which is a `PromiseLike<ExecResult>`
you can consume whichever way suits the call site:

```ts
const { stdout, exitCode } = await sb.exec("npm ci"); // await the whole result
await sb.exec("npm test").pipe(process.stdout); // stream it somewhere

for await (const chunk of sb.exec("npm test").stdout()) {
  process.stdout.write(chunk); // or take it chunk by chunk
}
```

All three drive the same underlying stream — [exec & execCode](/docs/core/concepts/exec).

## Nothing runs unrecorded

Every sandbox created, every command run and every chunk it emitted is appended to a SQLite or Postgres
[ledger](/docs/core/storage) as it happens. That isn't a logging feature bolted on the side; it's what the next part
depends on.

## Checkpoint, then resume

`sb.checkpoint()` snapshots the container. `client.resume(sandboxId)` restores it and rebuilds a replay cache from
the ledger, so commands that already completed return their stored result instantly and only the unfinished work
runs again:

```
Original run              Resume
  exec  "pip install"  →    replayed from cache (instant)
  checkpoint()              —
  exec  "python run"   →    runs live on the restored container
```

A crashed pipeline picks up where it stopped instead of starting over —
[checkpoint and resume](/docs/core/concepts/snapshots).

## Fork a live container

```ts
await sb.exec("npm ci");
const fork = await sb.fork("after-install");
await Promise.all([sb.exec("npm test"), fork.exec("npm run build")]);
```

`sb.fork()` snapshots the sandbox and starts a second one from that point, without closing the first. Both keep
running from the same filesystem — install once, then run several things on top of it at the same time. It is
also what the Agent SDK's `spawn()` is built on — [forking sandboxes](/docs/core/concepts/forking).

## Where this sits

The Core SDK is the substrate. The [Agent SDK](/docs/agent) runs coding agents inside these sandboxes,
[alineod](/docs/alineod) orchestrates trees of those agents, and the [Workflow SDK](/docs/workflow) adds a lazy
builder over the primitives here.
